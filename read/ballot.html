HackNH2020 / Ballot Buss

Ride coordination with an Android client and Python planner.

Android / JavaPythonrouting/planning

The idea

Ballot Buss is a hackathon team project around coordinating rides, with an Android client and Python planning/database pieces. For a learning-focused portfolio, the interesting part is the compressed collaboration: how a mobile interface, a record model and assignment logic meet at a shared contract. Joey's commits support database work, read tests, a homescreen and an icon. The wider routing algorithm belongs to the team context and is not attributed to Joey simply because his account contains a fork.

How it works

The intended workflow captures drivers and passengers, records capacities and locations, then generates assignments that the client can display.

The planner models driver capacity and passenger groups; a plan scores remaining unassigned passengers.

The Android client was inspected through source structure but was not rebuilt or connected to historical services.

Inside the build

A shared data model

Driver and Passenger classes make capacity, coordinates and groups explicit. Plan keeps a copy of routes and a score based on unassigned passengers. This is a concrete example of application state needing to be meaningful across components.

Assignment with constraints

The planner orders passengers by distance and explores assignments subject to available capacity. The local fixture uses the original generate_plan path and obtains a complete plan for a small synthetic case. That is not a city-scale routing benchmark.

Android meets Python

The repository includes Java Android activities and networking types alongside a Python server/planner. Joey's database and interface commits are specific evidence of contribution to those integration boundaries.

What I learned

Team integration under a short deadline

The source and commit sequence support learning about defining records, checking reads, and making a homescreen connect to the rest of a prototype. This is not a claim about the project's competition result or deployment impact.

Keeping attribution useful

A fork can still contain meaningful work. Naming the concrete commits—database rewrite/tests, homescreen and icon—communicates more than either claiming the entire system or excluding a collaborative project entirely.
